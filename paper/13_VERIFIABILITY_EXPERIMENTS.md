## 0. 为什么换因变量

| | 原 C2 | 现 C2 |
|---|---|---|
| 因变量 | 幻觉修正率 | **核查成本**（C2a）+ **审计可复现性**（C2b） |
| 受基座模型能力影响？ | ✅ 强（饱和到 100%，无法区分） | ❌ **完全不受影响**（纯确定性） |
| 需要模型犯错？ | ✅ 需要（但模型几乎不犯错） | ❌ **不需要** |
| 成本 | 300 次调用 / 3.7 h | **¥0 / 秒级** |

> 关键洞察：**「可核查」是关于证据的表示形式，不是关于模型的输出质量。**
> 因此它可以在**模型 100% 正确**的情况下被完整测量——天花板效应打不到它。

## 1. C2a｜核查成本

### 1.1 定义

验证一条主张（item 的某个字段值）需要比对多少个单元格？

| 体制 | 核对过程 | 单元格数 |
|---|---|---|
| **locator** | 证据携带 $\ell=(\text{sheet},\text{row},\text{col})$，直接寻址 $\rho(\ell,D)$ | **1**（构造保证） |
| **自然语言** | 消息只有措辞（「第 6 项的数量与原文不一致」），**不携带任何结构信息**；要变成可执行核对，必须先构造「措辞 → 单元格」的解析规则。在不假设文档结构的前提下，搜索空间 = 区域全部单元格 | **$\lvert D \rvert$** |

> **诚实声明**：$\lvert D \rvert$ 是**下界**而非精确值。若核查方额外假设
> 「表头在第 1 行、明细行按序号连续」，则可把成本降到 $O(1)$——但**这个假设本身
> 就是一段不可核查的代码**，而且换一个文档模板就要重写。locator 体制的 1 格
> 是**消息自身保证的**，不依赖任何外部假设。论文必须写明这一点。

### 1.2 实测结果（240 个测试订单）

| 指标 | 值 |
|---|---|
| 订单数 | **240** |
| 区域单元格数 均值 / 中位数 | **292.1 / 288.0** |
| 区域单元格数 范围 | [256, 336] |
| 每条主张的比对格数：locator | **1** |
| 每条主张的比对格数：自然语言 | **292.1** |
| **成本比** | **292.1 : 1** |

### 1.3 一个附带的硬结果：定位符真的能解析

| 指标 | 值 |
|---|---|
| 检查的主张数 | **23,528** |
| 成功解析 $\rho(\ell,D)=v$ 的 | **23,528** |
| **解析成功率** | **1.0000** |
| 不一致 | **0** |

> **这直接补上了待决事项 D16**：论文定义「$e$ 可复现 $\iff \rho(\ell,D)=v$」，
> 而代码里 `Evidence.reproducible` 只是**生产者自报的布尔值**（恒为 `True`，
> 从未真的 resolve）。现在有了独立于该字段的实测：**在 23,528 条真实证据上，
> 定位符 100% 解析回原值**。定义与实现之间的缺口被实测数据填上了。

## 2. C2b｜审计可复现性缺口 ★ **最有冲击力的结果**

### 2.1 定义

一条驳回要能被**第三方**复现，产物里必须留下**机器可核查的证据**。
本项统计：既有运行产物中，有多少条记录带了这样的证据链。

### 2.2 实测结果

| 指标 | 值 |
|---|---|
| 历史运行记录 | **423** 条 |
| 带机器可核查证据链的 | **0** 条 |
| **审计可复现性** | **0.0000** |
| 问题描述（`risk_result.issues`） | **1,676** 条 |
| 其中带定位符的 | **0** 条 |
| **问题可核查率** | **0.0000** |

各运行明细：

| 运行 | 记录 | 带证据链 | 问题 | 带定位符 |
|---|---|---|---|---|
| `baseline_generated_complex_test_20260910_234250` | 240 | 0 | 609 | 0 |
| `cord_v2_test_20260911_012942` | 100 | 0 | 1058 | 0 |
| `mfg_generated_test_smoke_20260910_232643` | 3 | 0 | 9 | 0 |
| （6 个 novelty 实验运行） | 80 | 0 | 0 | 0 |

### 2.3 这个 0% 意味着什么

产物里唯一留存的「问题说明」长这样：

```json
{"item_index": 23, "issue_type": "price_abnormal",
 "description": "单价 23.36 相对于参考价格 4.16 异常", "severity": "medium"}
```

**`description` 是自然语言**——正是 VEAP 设计要取代的那种不可核查形式。

> **这是论文里最有力的一段论证**：
> 系统在**运行时**确实构造了机器可核查的证据（§1.3：23,528 条全部可解析），
> 但**在落盘时把它丢掉了**，只留下最终值与自然语言描述。
> 于是「可核查性」这个性质**在协议层成立、在产物层不成立**。
>
> 缺口不在协议，在**持久化**。这是一个**可定位、可修复、且可度量**的工程缺口——
> 比「我们的机制提升了 X%」更经得起审稿。

### 2.4 修复方向（待实施，约 30 行）

把证据链写入运行产物：

1. `application/protocol/adversarial.py` 的 `challenge_evidence()` 已产出
   `Evidence(kind, locator, value)`，只需在落盘路径上带上它；
2. `final_result` 增加 `evidence_chain` 字段：每条主张 → `(locator, value, verdict)`；
3. `risk_result.issues[]` 增加 `locator`，把 `description` 从**唯一**说明降为**附注**。

**修复后可获得的实证**：审计可复现性 **0% → 100%**，且复现**不调用任何模型**
（验证者是确定性纯函数，C1 已用可执行断言守卫）。

> ⚠️ **为什么现在还没做**：生产代码属于冻结基线 `paper-v1-baseline`（`a596bd6`），
> 改动需重新打 tag（`paper-v2`）并说明「哪些实验基于哪个版本」。
> 这是**必须显式决策**的事，见待决事项 **D21**。

## 3. 这两项实验如何支撑论文

| 章节 | 用法 |
|---|---|
| §1 Introduction | 用 C2b 的 **0%** 立论：现有系统的「验证」是自然语言的，第三方无法复核 |
| §3 Problem Formulation | $\rho(\ell,D)$ 的定义 + §1.3 的 **1.0000 解析率**作为定义可实现性的证据 |
| §4 Method | VEAP 的三条约束；locator 使核对降为 $O(1)$（§1.2 的 **292:1**） |
| §5 Evaluation | **E7 核查成本** + **E8 审计可复现性**；并**如实报告 G0 的负面结果**作为适用边界 |
| §6 Discussion | 「可核查性是表示形式问题，不是模型能力问题」——解释为什么 G0 失败而 C2 成立 |

### 与 G0 负面结果的正确并置写法

> 「当基座模型自身足够准确时，反馈媒介的形态不产生可测差异（§12：三档模型、
> 两档难度、50 次调用、0 个正向 discordant pair）。这一负面结果**界定了机制的适用边界**：
> locator 的价值不在『让模型答得更对』，而在**使核对与审计成为可能**——
> 它把一条主张的核对成本从 292 格降到 1 格（§1.2），
> 并让驳回在不调用模型的前提下可被第三方复现（§2）。」

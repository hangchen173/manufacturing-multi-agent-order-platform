## 0. 定位澄清（重要）

**「SCI 一区」与「CCF」是两个交叉的分类轴，不是同一轴上的高低档。**

## 1. 核心研究问题

### 主问题

> 在结构化文档的字段抽取中，当验证者与生产者产生分歧时，**反馈信号的形态**如何影响错误检出率与计算成本？

### 子问题

| 编号 | 问题 | 对应贡献 |
|---|---|---|
| **RQ1** | 屏蔽生产者置信度的独立验证者，相比自我确认，幻觉检出率提升多少？ | C1 |
| **RQ2** | 以**机器可核查的定位符**作为挑战媒介，相比**自然语言论证**，检出率提升多少？ | C2（核心） |
| **RQ3** | 该机制在什么计算预算区间有效？超出后如何退化？ | C3 |

**RQ2 是整篇论文的支点。** 它来自项目中一个已存在但未被当作主张的设计：`application/protocol/adversarial.py` 的 `build_counter_evidence_feedback()` 只回灌可复现证据（locator + 原文值），不回灌验证者的自然语言措辞。

### 建议标题

- **中文**：证据锚定的对抗验证：以机器可核查定位符作为辩论媒介的结构化文档抽取方法
- **英文**：Evidence-Anchored Adversarial Verification: Machine-Checkable Locators as the Debate Medium for LLM-Based Structured Document Extraction

## 2. 创新点（3 条）

| 编号 | 贡献 | 类型 | 证据来源 |
|---|---|---|---|
| **C1** | **证据锚定的对抗验证协议**——挑战必须以「定位符 + 原文值」形式给出；反馈回灌时剔除自然语言措辞，使验证过程可程序化复核 | 机制 | 主对照实验 |
| **C2** | **证据形态的对照实证**——量化「定位符反证」vs「自然语言反证」对幻觉检出率的影响 | 实证（核心） | 消融实验 A1 |
| **C3** | **成本-效果边界**——统一计算预算下的 Pareto 分析，给出有效预算区间与退化行为 | 边界 | 预算扫描 |

### 贡献声明草稿（Introduction 末尾用）

> 本文提出证据锚定的对抗验证机制，将多智能体辩论的媒介从自然语言论证改为机器可核查的定位符证据，使验证过程可程序化复核。在 N 个数据集上，该机制相比自然语言辩论将幻觉检出率从 A 提升至 B（p < 0.05），并给出统一计算预算下的有效区间。

## 4. 需补充的实验与对比基线

### 4.1 数据集（≥4 个）

| 数据集 | 语言 | 类型 | 现状 |
|---|---|---|---|
| **自建制造业采购订单** | 中 | 订单 | 240+ 样本，**主场景** |
| FUNSD | 英 | 表单 | `datasets/public/` 已有 |
| CORD | 英 | 收据 | 已有，**但当前 0/100，须先修** |
| XFUND-zh | 中 | 表单 | 已有，用于中文泛化验证 |
| SROIE | 英 | 收据 | 已有，可选 |

**关键动作**：CORD 上 0/100 的问题必须先解决，否则跨域能力无法证明。若确实无法解决，须在 Discussion 中作为**边界声明**如实呈现（说明系统面向制造业订单而非零售收据，并解释字段与术语体系的结构性差异）。

### 4.2 对比基线（≥8 个）

| # | 基线 | 论文出处 | 作用 |
|---|---|---|---|
| 1 | Zero-shot 单 Agent 直抽 | — | 最低基线 |
| 2 | CoT | Wei et al. 2022 | 推理增强基线 |
| 3 | **Self-consistency** | Wang et al. 2023 | **必须比**（你反对的基线） |
| 4 | **Self-Refine** | Madaan et al. 2023 | ACL 2026 证明其低于 CoT，你要解释为何外部验证者能超越 |
| 5 | Reflexion | Shinn et al. 2023 | 自我反思线 |
| 6 | **MAD** | Du et al. 2023 | **核心对比对象** |
| 7 | LLM-as-a-Judge | Zheng et al. 2023 | 常见验证替代方案 |
| 8 | **MoA** | Wang et al. 2024 | ACL 2026 的 Pareto 最优，最强对手 |
| — | **本文方法 + 自然语言反馈** | 本文变体 | **内部消融基线，即 RQ2 的对照** |

### 4.3 评估指标

| 指标 | 说明 |
|---|---|
| 字段级 Precision / Recall / F1 | 标准抽取指标 |
| 幻觉率 | 抽取值与原文不符的比例 |
| **幻觉检出率（detection recall）** | **核心指标** |
| 误挑战率（false challenge rate） | 验证者错误挑战正确值的比例 |
| 决策准确率 | auto-approve / auto-correct / manual-review 三分类 |
| 成本 | tokens、LLM 调用次数、端到端延迟 |
| **Pareto 前沿** | 给定预算下的最高 F1 |

### 4.4 消融实验

| 编号 | 消融项 | 验证什么 |
|---|---|---|
| **A1** | **证据形态：定位符 vs 自然语言** | **C2 的核心对照** |
| A2 | 上下文隔离：屏蔽 vs 不屏蔽置信度 | C1 的必要性（V4 断言是雏形） |
| A3 | 验证者数量：1 / 2 / 3 | 规模效应 |
| A4 | 预算上限：多档位扫描 | C3 |
| A5 | 模型规模：8B vs 70B | 容量 vs 机制 |
| A6 | 去掉预算熔断 | 工程机制的必要性 |

### 4.5 统计严谨性

- 每个配置至少 **3 次运行**（LLM 非确定性）
- 报告 **均值 ± 标准差**
- **Bootstrap 置信区间**
- 关键对比做**配对显著性检验**

### 4.6 成本提醒

7 个外部基线 × 4 个数据集 × 3 次重复，LLM 调用量会到**数万次量级**。建议：先用小模型（8B 级）打通全流程，再用大模型跑最终结果；优先使用本地可部署的开源模型。项目已有的 run manifest 机制会自动记录 token 消耗。

## 6. 从现有项目提炼贡献的具体步骤

### 步骤 1：冻结版本（半天）

```bash
git tag paper-v1-baseline
git rev-parse HEAD   # 记录 commit hash，论文中需报告代码版本
```

### 步骤 2：术语翻译（1 天）

把工程语言翻译成学术语言。**这是最容易被忽略但极其重要的一步**——审稿人看不懂「黑板」「言后行为」这类自造词。

| 项目中的叫法 | 论文中的表述 |
|---|---|
| 黑板 | shared blackboard / structured message bus |
| 对抗协议 | adversarial verification protocol |
| 上下文切片 | context isolation / selective information hiding |
| 预算熔断 | budget-constrained escalation |
| 任务 DAG | task dependency graph |
| 可复现证据 | machine-checkable evidence / verifiable locator |
| 言后行为 | speech act / performative |
| 终裁 | adjudication |

### 步骤 3：提炼贡献（2 天）

用一句话回答：「别人没做到的、我做到了什么？」若答不上，说明贡献尚未成立。

### 步骤 4：改写方法章（1 周）

把 `MULTI_AGENT_DESIGN.md` 从「设计文档」语气改为「方法论述」语气，补伪代码与复杂度分析。

### 步骤 5：改造实验基建（1 周）

`evaluation/run_evaluation.py` 已具备批量评测与 run manifest 能力，需扩展：
- 支持多基线切换
- 输出论文级表格（LaTeX）
- 支持多次重复运行与统计

### 步骤 6：跑实验（4–6 周）

先小模型打通，再大模型跑最终结果。

### 步骤 7：写作与润色（3–4 周）

英文写作需母语级润色。建议先用中文写完整逻辑，再翻译。

# 制造业多 Agent 订单解析系统评测方案

## 1. 评测目标

本项目的评测目标不是证明“模型能跑”，而是证明以下四件事：

1. 系统在公开 benchmark 上具备通用文档理解能力。
2. 系统在接近真实业务的订单/票据/表单场景上具备结构化抽取能力。
3. 系统在脏数据、扫描件、复杂布局下具备鲁棒性。
4. 系统的 Agent 流程不仅能抽取字段，还能做物料匹配与人工确认分流。

适用场景：

- 考研复试项目讲解
- Agent 开发实习/校招简历项目
- 项目中期答辩或作品集展示

## 2. 推荐评测数据组合

建议采用 `公开 benchmark + 自建制造业订单集` 的双轨评测。

### 2.1 必选公开数据集

#### A. XFUND 中文子集

- 作用：验证中文表单理解、key-value 抽取、布局理解。
- 适配项目价值：最适合解释“为什么项目不仅是 OCR，而是文档理解 + 结构化抽取”。
- 官方链接：
  - GitHub: https://github.com/doc-analysis/XFUND
  - 论文: https://aclanthology.org/2022.findings-acl.253/
- 官方说明摘要：该数据集提供 7 种语言的人类标注表单数据，包含中文子集。
- 许可：GitHub 页面显示为 `CC BY-NC-SA 4.0`。用于学习、复试、求职展示通常可接受，但不要直接作为商业数据资产宣传。

#### B. CORD

- 作用：验证收据/票据结构化抽取、行项目抽取、扫描件解析。
- 适配项目价值：很适合展示“真实票据文档上的字段抽取与层级解析能力”。
- 官方链接：
  - GitHub: https://github.com/clovaai/cord
- 官方说明摘要：CLOVA 发布的 receipt parsing 数据集，GitHub 页面说明包含 over 11,000 receipts，公开样本版本可直接使用。
- 许可：GitHub 页面显示为 `CC-BY-4.0`。

#### C. SROIE

- 作用：验证 OCR + key information extraction 基础能力。
- 适配项目价值：适合讲“扫描噪声、低质量图像、票据字段抽取”。
- 官方链接：
  - ICDAR2019 SROIE 结果页: https://rrc.cvc.uab.es/?ch=13&com=evaluation&d=1&e=1&f=1&p=0&s=0&task=3
  - 可用镜像数据卡: https://huggingface.co/datasets/jsdnrs/ICDAR2019-SROIE
- 官方说明摘要：SROIE 是 ICDAR 2019 收据 OCR 与信息抽取竞赛数据集，包含真实扫描收据与关键字段标注。
- 使用建议：如果原始下载不方便，可以记录“原始 benchmark 为 ICDAR2019 SROIE，实验使用社区整理镜像以便统一读取”。

### 2.2 可选增强数据集

#### D. DocVQA

- 作用：验证“系统是否真正理解文档内容”，适合扩展为 Agent 问答能力。
- 官方链接：
  - 官网: https://www.docvqa.org/datasets/docvqa
- 官方说明摘要：DocVQA 官方页面说明该数据集包含约 50K questions 和 12K document images。
- 使用建议：如果你后续把项目扩展为“订单问答 Agent”或“采购单审阅 Agent”，这个数据集很加分。

#### E. FUNSD

- 作用：验证 noisy scanned forms 的表单理解能力。
- 官方链接：
  - GitHub: https://github.com/crcresearch/FUNSD
- 使用建议：可作为补充，不建议作为主展示集。因为对制造业订单场景的贴近程度不如 XFUND 中文子集。

## 3. 最推荐的展示组合

如果目标是考研复试或求职展示，最推荐：

1. `XFUND 中文子集`
2. `CORD 或 SROIE`
3. `自建制造业订单验证集`

原因：

- XFUND 证明你有中文表单理解能力。
- CORD/SROIE 证明你有扫描件和票据抽取能力。
- 自建订单集证明你真正做了业务落地，而不是只跑 benchmark。

## 4. 自建数据集要求

自建数据集不需要很大，但必须规范。

推荐规模：

- 最低可展示版：60 到 100 份
- 较完整版：200 到 300 份
- 优秀版：500 份以上

### 4.1 数据分层要求

自建制造业订单集至少覆盖以下分布：

#### 文档来源类型

- 文本型订单：20%
- 表格型 PDF：30%
- 扫描件/拍照件：30%
- 图片订单/聊天截图转图片：20%

#### 布局复杂度

- 简单单列表头：30%
- 多列表格：40%
- 混合文本 + 表格：20%
- 含盖章/水印/手写标记：10%

#### 质量扰动

- 清晰原件：40%
- 低分辨率：20%
- 模糊/压缩：15%
- 旋转/倾斜：10%
- 阴影/遮挡/裁边：15%

#### 业务字段完整度

- 字段齐全：40%
- 缺失单价或交期：20%
- 缺失客户或订单号：20%
- 含歧义物料名或简称：20%

### 4.2 每份订单至少应标注的字段

订单级字段：

- `order_number`
- `customer_name`
- `document_type`
- `currency`
- `total_amount`

行项目字段：

- `line_index`
- `material_name_raw`
- `specification_raw`
- `quantity`
- `unit`
- `unit_price`
- `delivery_date`
- `golden_sku_code`
- `risk_expected`

人工确认相关字段：

- `needs_manual_confirmation`
- `manual_confirmation_reason`

## 5. 自建数据集的合法构建方法

### 方法 1：模板合成法

最推荐，合法且最容易控质量。

步骤：

1. 设计 10 到 20 套制造业订单模板。
2. 每套模板变换字段布局、表头、字体、公司名、日期格式、币种格式。
3. 用真实但不涉密的通用物料名称构造行项目。
4. 导出为 PDF、图片、扫描版。
5. 做模糊、噪点、旋转、阴影、压缩等增强。

优点：

- 100% 可控
- 没有隐私风险
- 适合大批量生成

缺点：

- 真实性弱于历史业务单据

### 方法 2：公开采购文档改写法

适合增强“真实感”。

步骤：

1. 从合法公开来源获取采购或招投标 PDF。
2. 抽取其中物料名称、规格、数量、交期表达。
3. 改写为自建订单模板，不直接复用原文全文。
4. 重新排版成订单、采购单、询价单等格式。

优点：

- 语言更真实
- 规格表达更接近工业场景

缺点：

- 需要人工清洗和改写

### 方法 3：少量真实脱敏订单法

如果你能拿到校企合作或实习中的历史样本，这是最有说服力的方法。

要求：

- 删除公司名称、联系人、电话、地址、银行信息、合同编号等敏感信息
- 替换客户名与供应商名为匿名标识
- 保留物料表达、规格格式、表格布局、扫描噪声

建议用量：

- 30 到 50 份即可作为“真实脱敏验证集”

### 不建议的方式

- 直接爬取网络发票或商业单据
- 使用来源不明的网盘数据
- 未脱敏就存储真实业务单据
- 用大模型随机生成完全同质化订单作为唯一验证集

## 6. 评测指标

### 6.1 订单解析能力

- 订单级字段准确率
- 行项目字段准确率
- 完整订单解析成功率
- 低质量文档解析成功率

### 6.2 物料匹配能力

- SKU Top-1 准确率
- SKU Top-3 命中率
- 未匹配召回率
- 错配率

### 6.3 风控与人工确认能力

- `needs_confirmation` 命中率
- 风险问题召回率
- 风险误报率
- 人工确认分流率

### 6.4 系统工程指标

- 单文档平均处理时延
- 单文档平均 API 成本
- 异常文档失败率

## 7. 推荐评测切分

### Phase 1：公开 benchmark

- XFUND 中文：50 到 100 份
- CORD：100 份
- SROIE：100 份

目标：

- 证明系统有通用文档理解能力

### Phase 2：自建制造业订单集

- 清晰件：40 份
- 表格复杂件：30 份
- 扫描件：20 份
- 强干扰件：10 份

目标：

- 证明系统与制造业订单场景贴合

### Phase 3：对抗鲁棒性集

- 旋转
- 模糊
- 压缩
- 阴影
- 裁边
- 水印

每类 10 到 20 份即可。

目标：

- 证明系统不是只会做干净样本

## 8. 复试/简历展示建议

最适合讲的结果结构：

1. 公开 benchmark 上的字段抽取能力
2. 自建订单集上的业务字段与 SKU 匹配能力
3. 脏数据条件下的鲁棒性
4. Agent 决策带来的人工确认率下降

简历表述建议：

`基于公开文档理解 benchmark（XFUND/SROIE/CORD）和自建制造业订单数据集，完成订单解析、物料匹配、风险确认流程验证。`

避免写：

`已在生产环境大规模验证`

更稳妥的写法：

`在公开 benchmark 与自建模拟/脱敏数据上完成系统性评测`

## 9. 执行顺序

1. 下载并登记公开数据集来源与许可。
2. 在 `evaluation/manifests/` 中记录每个数据源的采样清单。
3. 用 `evaluation/templates/annotation_schema.example.json` 统一标注格式。
4. 先做 30 份小样本试评测，检查字段定义是否合理。
5. 再扩展到正式评测规模。
6. 用 `evaluation/templates/result_summary_template.md` 汇总结果。

## 10. 本目录配套文件

- 标注模板：`evaluation/templates/annotation_schema.example.json`
- 自建数据清单模板：`evaluation/templates/self_built_manifest.example.csv`
- 结果汇总模板：`evaluation/templates/result_summary_template.md`
